## 完成：节点配置云端同步 + 本地代码导出

### 问题背景
- 用户在网页上通过"编辑进度节点"修改的节点配置只保存在浏览器 localStorage 中
- 换电脑/浏览器后看到的是代码里的默认配置，不是用户自定义的配置
- 本地代码中的 DEFAULT_PHASES 和用户实际使用的配置不一致

### 解决方案
1. **后端 server.js**：
   - 扩展 data.json 默认结构，兼容旧数据（无 `phases` 字段的情况）
   - 现有 API `/api/data` 已经支持保存/读取 `storePhases` 字段

2. **前端 进度管理系统.html**：
   - 页面加载时优先从服务器读取节点配置，覆盖默认值
   - 服务器没有配置时，自动把本地配置（localStorage 或 DEFAULT_PHASES）上传到服务器
   - 轮询同步（每5秒）现在也能检测节点配置的变化并自动更新
   - "编辑进度节点"保存后自动同步到服务器
   - 添加"导出配置"按钮，一键生成可直接替换代码的 JS 格式 + JSON 备份

### 使用方法
**多设备同步：**
1. 在任意设备上编辑节点 → 点"保存修改"
2. 配置自动保存到服务器
3. 其他设备刷新页面即可看到最新配置

**同步到本地代码（让我读取最新配置）：**
1. 打开"编辑进度节点"
2. 点"📋 导出配置"按钮
3. JS 代码自动复制到剪贴板
4. 粘贴发给我，我立即更新本地 `进度管理系统.html` 里的 `DEFAULT_PHASES`

## 完成：pm2 进程守护配置 + Nginx 代理修复

### 问题
后端 Node.js 进程长时间运行后僵死（PID 存在但端口不监听），导致"授权服务暂时不可用"。

### 解决
1. **安装 pm2**：`npm install -g pm2`
2. **pm2 启动后端**：`pm2 start server.js --name store-api`（自动守护、崩溃重启）
3. **开机自启**：`pm2 startup` + `pm2 save`
4. **端口调整**：后端自动切换到 3003（3002 被旧进程占用）
5. **Nginx 修复**：两个配置文件都更新为代理到 3003
   - `/etc/nginx/conf.d/store-progress.conf`
   - `/etc/nginx/default.d/store-progress.conf`
6. **验证**：`curl http://localhost/api/data` 正常返回

### 后续保障
- 后端崩溃后 pm2 会自动重启
- 服务器重启后 pm2 会自动启动 store-api
- 查看日志：`pm2 logs store-api`
- 查看状态：`pm2 status`
